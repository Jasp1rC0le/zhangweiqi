# 商家照片运维导入

这是站点所有者通过已有部署SSH权限运行的离线命令，不是面向访客的HTTP接口。它不创建管理员、登录令牌或新凭据，不执行DDL、发送模型请求或更改评分。执行前人工核对固定清单及用户授权；实际调用应用的商家/照片服务和事务。

输入清单版本1，包含唯一活动学校名、已发布食堂名及商家列表；每家包含名称、位置、说明、1–10份照片的路径和SHA256。已有商家必须同时指定原编号与预期名称，防止覆盖已变化的条目。所有图片必须位于清单旁的 `photos/` 下，拒绝符号链接或目录外文件。每张5MB，整份清单100张/120MB上限。清单本身亦须通过显式SHA核对。

运行顺序：备份 → 核对目标学校/食堂/已有记录 → `--check` → 人工核对回执 → `--apply` → 回读实际商家和照片、核对原评分未变。两种命令均需独立且不存在的回执路径；检查模式不写入，检查模式只检查清单、文件完整性及目标元数据，图片解码在应用事务中再次校验。应用模式全部商家共用一个事务，末张坏图或数据库冲突会回滚此前本批写入。未知结果不能自动重发，应先按清单与实际库核对。

主类 `com.campusai.operations.MerchantPhotoImport`，通过Spring Boot `PropertiesLauncher` 显式选择，参数为 `--check|--apply manifest.json expected-sha256 receipt.json`。使用服务账号及原生产EnvironmentFile，强制SQL-init never；仅CLI profile加载JDBC和商家服务，不启动Web端口、后台任务、邮件测试或知识种子。当前网站照常运行，表结构准备由独立受控迁移完成。

菜单额外照片迁移为 `deploy/migrations/2026-10-31-merchant-gallery.sql`，只新增 `campus_merchant_photo_gallery`。没有自动迁移入口；旧封面和评分仍用原表。照片统一重编码并移除元数据，完整菜单最长边2400，评分列表派生预览最长边720。派生缓存最多64份，每次仍重新核对商家/食堂发布状态，不能在下架后凭缓存继续返回。

真实商家和照片不进入公共Git仓库。回执应明确注明SSH运维导入，不能写成已通过网页管理员会话操作；公开知识资料继续单独遵循官网资料审核与发布流程。
