# 隐私与网络边界加固

范围：本地代码、隔离测试、生产部署模板。未操作真实账号、未清理生产数据、未部署，不是完整渗透测试或合规认证。

## 本轮修复

1. **跨站请求**：所有 API 非只读请求检查 Origin；无 Origin 时验证 Referer，再参考 Fetch Metadata。认证、刷新和退出必须有可信 Origin/Referer，不能仅依赖 SameSite Cookie。来源严格匹配配置，不信任 Host 或前缀匹配。开发的前后端不同端口通过明确配置支持；命令行调用认证接口也须提供实际允许的 Origin。非浏览器 Bearer API 客户端保留支持，身份仍由拦截器核验。
2. **缓存与报错**：API（含未认证错误）默认 no-store、nosniff、防嵌入、no-referrer。流式回答禁止缓存，不再回显底层异常；未知数据库异常与坏 JSON 使用通用提示，不返回 SQL、连接地址、堆栈或请求原文。自定义业务错误不等于全局日志脱敏已完成。
3. **公开接口防刷**：注册每来源地址每15分钟30次、反馈60次；计数复用数据库原子更新，存摘要不存明文IP。不用用户传入的转发头；单机本地代理必须覆盖转发头。校园共享网络可能共享额度，需观察误拦截后调整。不是 DDoS 防御或验证码系统。
4. **反馈隐私**：已登录反馈必须验证令牌，并绑定服务器确认的用户与学校；能进入本人导出/注销范围。管理员仅能读取和处理本校反馈，列表最多200条。访客反馈需要显式 `CONTACT_SCHOOL_ID` 路由；默认0时返回503并提示登录或联系邮箱，不将访客隐私送到所有学校管理员。旧版 user_id/school_id 为空的记录不能凭昵称自动补归属，留待受控人工核验。
5. **过期共享副本**：审阅7天到期立即禁止读取，新增每小时任务清空已过期/撤销快照和意见；原项目与其版本不动。保留邀请元信息，随项目或账号删除。任务启动后延迟1分钟首次运行；停机期间不承诺实际物理删除时间。隐私页已同步说明；备份不在此任务范围。
6. **生产部署**：prod 禁止自动执行 schema.sql，并禁用旧的启动索引迁移组件；默认关闭学校/企业样例种子。迁移须由独立账号受控执行。数据库就绪检查由8表扩展到21表，包括校园墙、会话、审阅、额度等，仍不是列/索引/外键一致性证明。
7. **代理模板**：保留 HTTPS/CSP 等配置，增加40MB请求上限、隐藏开发预览和敏感点文件、覆盖客户端转发头。服务器只监听 loopback；不能把 Java 端口直接公开。生产错误页不包含消息、绑定错误或堆栈。

## 兼容性与部署注意

- 配置来源须是精确的 `https://域名[:端口]`，不能含路径、尾斜杠、用户名、查询串、片段或通配符。Web 与 API 如分域部署，重新验证 Cookie/CORS；不要将失败的跨站校验改成通配放行。
- `CONTACT_SCHOOL_ID` 必须来自真实 schools 表，确认哪所学校的管理员承担访客反馈处理。登录用户提交不依赖此配置。官方联系邮箱保留为 contact@campthinkhub.cn。
- 新代码重启后清理任务会按上述规则清空已到期审阅副本和意见，恢复备份可能让旧副本重新出现，恢复流程须再次执行到期清理。当前未对真实数据执行该任务。
- prod 不再自动修复表或索引。发布前备份、在隔离数据库验证迁移、核对21表和知识索引，再用无 DDL 权限的应用账号启动；不应靠临时给应用 root 权限绕过。
- Caddy 模板未在本机执行 `caddy validate`（未安装）；需在目标机器用实际域名执行验证。40MB为代理总量上限，后端仍有单文件8MB及multipart总量限制；模板未自动应用到现有 Nginx/Caddy。
- 全站仍使用测试阶段隐私文本。未擅自填写运营主体、第三方处理地点、备份期限，也未打开 `PRIVACY_POLICY_APPROVED`。
