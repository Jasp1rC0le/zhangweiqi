## 2. 额度和成本保护

| 配置 | 首发建议值 | 意义 |
| --- | --- | --- |
| `AI_DAILY_TOKEN_LIMIT` | 20000 | 每账号每日外部模型 Token 额度，已有预占与结算账本 |
| `AI_PLATFORM_DAILY_CNY` | 10 | 全站当日应用侧估算预算 |
| `AI_PLATFORM_MONTHLY_CNY` | 200 | 全站自然月应用侧估算预算 |
| `AI_MAX_INPUT_BYTES` | 48000 | 单次全部消息 UTF-8 字节及开销上限，避免长上下文失控 |
| `AI_MAX_CONCURRENT` | 4 | 单实例模型并发上限 |
| `AI_COST_ADMIN_USER_ID` | 必填真实管理员 ID | 只有此账号可看全站成本，其他管理员只能看本校成功回答用量 |

每日/每月按北京时间计算，两个预算同时生效。预算用完停止新模型请求，不影响本地项目工具。参数是首发建议，不是自动充值、收费授权或无限免费承诺。

新 `ai_provider_attempts` 逐次记录供应商请求，包括重试、备用模型；请求前同时预占日/月预算，数据库事务保证跨进程并发不重复放行。供应商返回完整用量后按请求发起时单价结算；失败、断流、缺失/不一致用量及进程崩溃保留预占，不把未知成本当 0。异常超出预占的真实用量会全额记账，阻止后续调用，不截断账单。

后台 → 模型用量 → 免费版预算，查看今日/本月调用、已确认输入输出 Token、估算费用、预算占用、待核对与失败数。下方原“24 小时用量”只代表本校已保存的回答，不是全站完整费用。历史调用不倒填到新账本。新账本不保存提问、回答、用户 ID、IP 或 Key。

**边界：这是按配置价格计算的应用保护，不是供应商账单硬上限。** 缓存、峰谷价、阶梯价格、模型别名、未返回用量、供应商计费规则变化都会造成差异。生产 API 使用独立项目/Key，小额预充值，不开自动充值；供应商有硬额度时同时启用。每天对账，不直接改预算表或随意退回失败预占。

### 费用怎么估

公式：输入 Token ÷ 1,000,000 × 输入单价 + 输出 Token ÷ 1,000,000 × 输出单价

2026-10-04 查到 DeepSeek Flash 高峰/未命中缓存单价为输入 2 元、输出 8 元/百万 Token；建议先按这个偏高口径设保护，不预先扣缓存或空闲时段折扣。[DeepSeek 官方价格](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)

例如每次输入 3000、输出 1000 Token，约 0.014 元；1000 次约 14 元。输入包含历史消息、系统指令与资料，不只是用户最后一句话。上述仅为假设场景，不是现有用户实际成本或用户数量预测。

服务器月成本、域名年费/12、备份存储、邮件、网络流量、后续搜索费用另计，不能声称“200 元就是全站一个月总成本”。Kimi K3 还存在缓存写入费用；没有完整费率时不启用，不使用网上二手人民币价格代替本账号账单。[Kimi 官方计费说明](https://platform.kimi.com/docs/pricing/chat)、[智谱官方价格](https://open.bigmodel.cn/pricing)

免费观察期建议两周。每晚保存供应商账单及预算页数字：请求量、输入/输出 Token、待核对数、失败数、模型费用；另记录真实注册数和运营反馈。当前未植入广告追踪、设备指纹或第三方访问统计，也不把请求次数当成访问人数。未有真实数据前不确定会员价格。

### 真实账单核对

后台 → 模型用量 → 免费版预算 → 选择开始/结束日期 → 导出对账明细。每次最多 31 天，界面结束日包含当天，服务端查询使用次日为排他上界。按北京时间日期、供应商、请求模型汇总；不导出用户 ID、提问、回答或密钥。只有 `AI_COST_ADMIN_USER_ID` 指定且当前有效的 ADMIN 可导出。

在模型官方控制台下载实际账单，保留原件；人工核对时区、币种、模型别名、折扣、缓存等项目，汇总成以下列，不填假数据：

```csv
date,provider,model,actualCny,currency,timezone
```

每个日期/供应商/模型只能一行；金额为核实后的人民币值，最多六位小数，币种填 `CNY`，时区填 `Asia/Shanghai`。供应商外币账单须有确定的换算依据，不能直接把美元填成元。随后本地运行：

```bash
node deploy/reconcile-costs.mjs /私有目录/应用导出.csv /私有目录/供应商日账单.csv
```

输出 `MATCH`、`AMOUNT_DIFF`、`UNRESOLVED_REQUESTS`、`MISSING_LEDGER` 或 `MISSING_BILL`；退出码分别为全匹配 0、待核对 1、文件无效 2。空文件不算通过。工具只比较文件，不证明账单真伪或覆盖完整性，不上传账单、不改额度、不自动释放未知请求的预占。本轮只用测试账单验证算法，尚无真实模型消费账单。

## 3. 构建与数据库

仓库根目录运行：

```bash
bash deploy/build-release.sh
```

脚本执行 Java 测试/打包、锁文件安装前端依赖、Node 测试、ESLint、生产构建；生成 `releases/free-时间-随机串/` 和同名压缩包，内含 JAR、静态页面、配置模板、校验和及部署说明，不包含 `.env`、数据库或源码目录。发布包目录只代表构建成功，不代表以下公网验收通过。

构建会重新安装锁定的前端依赖；若同时开着 Vite 开发服务，构建后重启该服务，避免旧预构建缓存返回 504。不要在生产服务器上用开发模式提供页面。

- 全新库：使用专用迁移账号执行包内 `schema-new-database-only.sql`，确认 49 张表。不要把测试库直接变为正式用户库
- 已有库：先备份，比较当前表、字段、索引及外键。按版本审查`V20261004__ai_spend.sql`（两张成本表）、`V20261009__contact_submission_keys.sql`（反馈重试凭据）及`2026-10-11-private-timetables.sql`（四张私有课表表）。反馈迁移要求`users`和`contact_messages`已存在；课表迁移要求`users`已存在。这些加法迁移不修改历史反馈或课表内容，不会修复其他旧结构，不能冒充完整历史迁移方案。以前版本结构不明时须先做实际结构差异评审
- 生产 Java 账号仅授予应用所需 SELECT/INSERT/UPDATE/DELETE，不用 root，不授予 ALTER/DROP。`prod` 禁止启动自动 DDL。管理员角色由运营在核实自有账号后受控赋予，注册请求不能指定 ADMIN
- `/api/health/ready` 检查数据库及 49 张必需表，缺少反馈凭据或私有课表表时返回503；不验证每个字段/索引，不可替代真实账户与业务测试。恢复旧备份缺少新表时，保留隔离恢复库，先执行增量迁移，再启动当前版后端核验

10月9日的审阅接口新增必填`baseNote`，新前端核对`noteConcurrencyVersion`；反馈页核对`requestIdVersion`。先在隔离库验证迁移，再协调更新后端与前端，提醒旧标签页刷新。不能通过取消这些校验让新旧版本静默混用。

本地隔离联调：`node deploy/local-smoke.mjs`。需要本机 MySQL 程序和已构建 JAR；新建临时库及回环服务，测试结束关闭自己的进程，不访问现有库。HTTP请求8秒、命令60秒、整轮180秒上限，超时或中断会执行清理；测试材料保留供核对，不自动删库。覆盖反馈并发去重/迁移保留、审阅冲突/撤销、真实Cookie刷新/旧令牌退出失效、账户导出及备份恢复。AI 与 SMTP 接收端为本地替身，不花付费 API 额度、不发真实邮件；这不是浏览器跨标签广播或真实邮箱送达验收。

`age`、`age-keygen` 和 MySQL CLI 在 PATH 时，运行 `SMOKE_ENCRYPTED_BACKUP=true node deploy/local-smoke.mjs`，还会实际加密备份、恢复到隔离新库、拒绝损坏密文和覆盖旧库。只在开发/专用验收机器执行，不用真实数据库目录。

## 4. 北京服务器部署顺序

**ICP 未通过前，不开放域名或 IP 的公众访问；本地测试不能代替备案。** 公网开放条件见第 7 节。

1. 确认服务器架构/系统、内存、磁盘和有效期；安装 Java 17、MySQL 8、Caddy、age。当前模板针对 Linux systemd 单机，不假定你的旧服务器已装齐
2. 创建无登录权限的 `campthink` 服务用户，发布包解压到独立的 `/opt/campthink/releases/版本/`，校验 `shasum -a 256 -c SHA256SUMS`。不要在正在使用的目录覆盖构建
3. `/opt/campthink/current` 指向本版本；静态目录 `/srv/campus-ai-web` 指向本版本 `web`。保留上一版，仅在停机维护或原子切换方案确认后改指向
4. 将 `server.env.example` 复制至 `/etc/campthink/server.env`，root 管理、权限 600，填真实数据库/模型/SMTP配置；设置 `SPRING_PROFILES_ACTIVE=prod,free`，`PUBLIC_WEB_URL=https://campthink.cn`、同源 CORS、安全 Cookie。不要把密码贴到聊天、命令行参数或前端变量
5. 核对后使用 `campthink.service` 启动。生产模式要求真实 `PRIVACY_OPERATOR_NAME`、`PRIVACY_CONTACT_EMAIL`、当前 `PRIVACY_POLICY_VERSION=2026-10-04`，以及政策审核、实际服务商、留存期限三项确认。未完成时保持 `PRIVACY_POLICY_APPROVED`、`PRIVACY_PROCESSORS_CONFIRMED`、`PRIVACY_RETENTION_CONFIRMED` 为 false，生产启动会拒绝；不能只改为 true 跳过审核。JVM 内存 768MB 是模板，需要根据机器总内存及解析负载调整
6. 备案通过且符合公开 AI/论坛服务要求后，使用 Caddy 模板配置真实域名。防火墙仅对公网开放 80/443；SSH 限管理员 IP，8080/3306 不公网开放。Java 只监听 127.0.0.1
7. Caddy 自动申请/续期证书，先执行 `caddy validate --config /etc/caddy/Caddyfile`，然后受控 reload；不要为了 HTTPS 绕过备案。没有备案时可按云商指引提前 DNS 验证申请证书，但不开放网站
8. HTTPS 下用专门验收账号验证注册、登录、刷新、退出、项目保存/导出/删除、校园墙审核、食堂评分、真实 AI 小额调用、预算保护、邮箱验证/找回。检查浏览器 Secure/HttpOnly Cookie、SSE、附件 worker、深层路由刷新、移动端与 HTTPS 跳转

前端 `campus-ai-web/.env.example` 支持真实运营主体、ICP 与公安备案号，填写后重建；未填显示内部测试，不显示虚假号码。正式 `/privacy` 文案与注册同意版本必须同步发布，不应保留“测试草案”又允许公开注册。

### 正式邮件

公开 MX 指向腾讯企业邮箱，因此已在模板预填 `smtp.exmail.qq.com:465`、SSL 及 `contact@campthinkhub.cn`，尚未填写密码。必须在实际邮箱后台确认该邮箱存在、SMTP 已授权、发件人匹配；只在服务器私有环境文件填授权码，不发给聊天或前端。[腾讯云 SMTP 配置说明](https://intl.cloud.tencent.com/document/product/1266/71700?lang=en)

## 5. 加密备份与恢复

提供 `backup-common.sh`、`backup-db.sh`、`restore-drill.sh` 和 `offsite-copy.sh`。备份/恢复支持 Linux 与 macOS，要求 MySQL CLI、age；凭据文件 400/600、备份目录 700。异地复制目标要求已配置并核验主机密钥的 Linux SSH 主机。示例中的路径必须由部署者建立，密钥不放仓库。

```bash
bash deploy/backup-db.sh /etc/campthink/backup.cnf campus_ai /var/backups/campthink age1真实公钥
bash deploy/offsite-copy.sh /本机绝对路径/backup-实际任务名 已配置SSH别名 /远端私有目录
bash deploy/restore-drill.sh /etc/campthink/restore.cnf /离线密钥路径/restore.agekey /备份任务目录 campthink_restore_20261004
```

备份使用一致性事务、gzip、age 加密流水线，磁盘上不落明文 SQL；输出密文和 SHA256。异地脚本仅传密文及固定格式校验文件，强制 SSH 主机密钥校验、拒绝覆盖远端同名任务、复制后复核哈希，不传私钥、不删旧备份。预先用可信渠道核对 SSH 指纹，不用 `StrictHostKeyChecking=no` 绕过。

备份文件传到独立存储位置，解密私钥离线单独保管；同盘备份不是容灾。恢复脚本先校验密文校验和、完成解密与 gzip 完整性验证，再建全新的 `campthink_restore_` 库导入，拒绝覆盖现有库，不自动删库。恢复完再启动隔离后端，禁用出站 AI/邮件，检查登录与数据隔离。工具不能单靠 SHA256 证明备份来源，也不能代替保管密钥和演练。

建议每天至少一次备份，发布/迁移前额外备份；目标 RPO ≤24 小时，目标 RTO ≤2 小时，均为目标而非已证实保证。建议普通备份保留 14 天，须运营确认、写入政策并配置真实生命周期。脚本故意不自动删除旧备份，未配置生命周期就不能承诺 14 天清除。法律要求保留的安全日志与业务备份分开制定，不以此 14 天覆盖法定义务。实际服务器加密备份及异机恢复尚未执行。

回滚：停止对外写入 → 保留故障现场并补备份 → 回到上一版应用与静态包。此次成本表是增量新增，应用回滚不删表。不要为了回滚应用直接覆盖数据库丢掉新用户数据；涉及数据损坏时先隔离恢复库核对，再审批切换。

## 6. 真实隐私与安全门槛

- 新个体工商户执照名称/经营者/地址、联系邮箱能真实收信

## 8. 深搜补充：不要混淆不同产品与验收结论

本节为2026-10-04续检结果，不改动此前本地测试记录，也不表示已操作生产环境。来源与核验局限见 资料台账 (local evidence retained privately) 的 O01—O16。

- **邮件产品区别**：当前模板面向腾讯企业邮箱的SMTP。另一个产品“腾讯云邮件推送”规定，2026-03-02起新开通服务的个人认证账号不能使用SMTP，可走API/控制台；该限制不能套用为企业邮箱不可用，也不能默认新个人账号能直接运行现有SMTP实现。若换成邮件推送API，需要另做服务适配和真实送达测试，不只换一个域名。[官方权限公告](https://cloud.tencent.com/announce/detail/2212)
- **发信域名区别**：网站是campthink.cn，联系邮箱属于campthinkhub.cn。SPF/DKIM/DMARC须配置在实际发信域且使用实际服务商提供的值；邮件推送示例不能直接覆盖企业邮箱现有MX/SPF。先保留既有收信功能，再核验发信。[邮件推送身份验证说明](https://cloud.tencent.com/document/product/1288/60652)
- **证书方案区别**：现有部署模板使用Caddy，不需要为查资料改成Nginx。腾讯云手动证书方案是另一种选择；重新签发后还需部署新证书，并非旧证书自动延期。任何方案都须检查实际域名的证书链、有效期和续期结果。[腾讯云续期说明](https://cloud.tencent.com/document/product/400/61353)
- **复制与恢复区别**：现有脚本使用SSH异地复制；COS只是另一种候选存储，不是本轮新增的已实现适配。COS复制需要版本控制等前置配置，历史版本产生存储费；不同地域、加密密钥独立保存、恢复到新库及业务检查仍需验收。[COS复制配置](https://cloud.tencent.com/document/product/436/19239)、[防误删实践](https://cloud.tencent.com/document/product/436/106495)
- **资料与账单区别**：Kimi计费文档确认缓存写入及输入输出计费差别；GLM价格页依赖动态渲染，DeepSeek价格页本轮直读超时。没有据此调整单价或宣称实际账单核对通过。保留原估算保护，启用前用当前账号、实际模型和账期重新确认。[Kimi计费](https://platform.kimi.com/docs/pricing/chat)
