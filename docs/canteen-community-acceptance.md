# 食堂口碑榜与隐私加固验收

日期：2026-09-23。范围：本地代码与开发演示，不表示已部署至公网或整个总体规划已经完成。

## 直接体验

前端开发服务运行时，打开 `http://localhost:5173/design-review.html?page=canteens`。

- 两个虚构食堂、五个虚构商家、三种原创餐食示意插画；每页明确标注测试数据。
- 点击星级，再保存评分；重复修改不增加评分人数。
- 展开短评，填写体验并保存，显示“待审核，仅你可见”。仅保存星级不会顺带上传正在编辑的短评。
- 神评可点赞、取消点赞。开发页右下角可模拟通过自己的短评审核，收起再展开可验证状态；该按钮不是生产后台。
- 搜索、食堂筛选、评分排序、无评价商家均可体验。
- 所有测试数据和互动仅在当前页面内存中，刷新恢复初始样例；不写真实数据库，不存浏览器本地存储。演示脚本不是生产构建入口。

## 正式功能代码

- 保留现有首页、登录、聊天，只重排食堂页。按照移动优先的信息层级展示商家、分数、神评和评分入口；5星体系保持不变，避免把旧5分数据误当10分。
- 评分一账号一商家一条，展示真实均值；综合排序沿用 `(总分+17.5)/(人数+5)` 平滑。不承诺此规则能识别多账号刷分。
- 点赞使用显式幂等 PUT：`/api/canteens/merchants/{id}/reviews/{reviewId}/like`，请求 `{liked:true/false}`。数据库复合主键防重复，审核文本行锁串行化点赞/改文案。
- 神评从本校已发布商家的已审核短评中按点赞数取第一，同赞按较新的短评ID；无赞时标记“同学说”。两次批量查询完成商家与神评数据，不逐商家发请求。
- 新增/修改短评先待审。修改文字会清除旧点赞；只改星级或提交相同文字不清空点赞。空文字明确删除短评及其点赞，但保留评分。
- 管理员审核必须提交其看到的 `expectedComment`，在事务中逐字核对；内容已变更返回409，避免审核旧页面时批准新文字。

## 安全与隐私边界

- 服务器从有效用户资料取得学校和角色，不信任客户端学校/用户ID；非学生账号不参与评分、点赞，停用账号拒绝访问。老师尚无独立已验证身份类型，不宣称完成教师认证。
- 跨校/未发布商家与未公开短评拒绝点赞，禁止本人给自己点赞；待审/隐藏短评只在作者自己的列表中返回，不进入神评。
- 公共返回不包含作者账号、姓名、点赞者名单；文本通过Vue插值展示，不作为HTML执行。评分、短评和点赞不发送给模型。
- 写入前限制500字，拦截控制字符，清理不可见格式字符；检测手机号、邮箱、18位身份证形式，检测时兼容全角字符，正常中文标点不改写。规则不是完整个人信息识别，也不能替代人工审核。
- 当前部署为单实例账号级每分钟30次写入限流，缓存上限1万账号，过期数据在后续调用时清理；不采集额外IP、设备指纹。重启会重置窗口，多实例部署需共享限流，不能将其宣传为完整反作弊。
- 自己的点赞加入账号导出；注销账户通过外键级联清理点赞，删除短评也清理对应点赞。数据库备份保留与删除期限仍需运营方明确。
