# 昵称、修改密码与邮箱找回

用户要求新增修改昵称、重置／忘记密码。本批补齐账户页的常显昵称编辑、当前密码改密和明显的邮箱找回入口，复用已有验证邮箱与一次性邮件流程，不新增表或第三方服务。

## 实际行为

- 账户页昵称直接保存并同步标题、头像字首和侧栏；只修改`users.nickname`，登录账号、学校、角色和已有业务数据不改。1—50字符，去首尾空白，拒绝换行／控制字符。更新由当前JWT会话确定账号，不接受请求体指定他人。
- 登录后可凭当前密码设置新密码并二次输入确认；验证失败不退出原会话。修改成功后本账号全部旧登录会话撤销，找回、待验证邮箱及私人日历授权失效；已验证邮箱保留。系统日历副本不会因此自动删除，其他账号不受影响。
- 当前客户端仅在同一账户／登录代际仍有效时清空密码、结束本地会话并返回登录。不会用改密响应的`Set-Cookie`覆盖另一个并发登录账号的Cookie；已撤销会话即使尚有旧Cookie也不能续期。服务器登录发会话前加用户行锁并复核已验证的密码哈希、角色及学校，防止改密前的认证结果在改密后再产生有效旧会话。
- 找回密码沿用“登录账号＋已验证邮箱”的20分钟一次性链接；不存在、不匹配或未绑定不返回账号存在状态。未绑定邮箱不能仅凭昵称重置。邮箱验证30分钟，重置仍要求收件人和当前绑定邮箱一致，旧链接不能换邮箱后复用。没有重发实际SMTP验收邮件。
- 新密码遵循既有6—72字符规则，同时限制UTF-8不超过72字节，避免BCrypt截断或内部错误；不修改密码原始字符。普通改密和邮件重置使用相同规则。
- 新字段仅在页面内存，换号、离开或成功后清空密码；旧响应不能保存到新账号。其他未保存资料会阻止直接改密退出。邮件页防重复提交、正确清空重试错误，同一组件路由复用时取消旧操作；一次性凭据从当前URL及路由history字段清理，不写入浏览器草稿。
